Open Smash in Obsidian when you want a richer notes UI.

Smash owns the memory lifecycle. Obsidian can be a comfortable editor and graph viewer for the same local Markdown files.

Import An Existing Obsidian Vault

Use smash import-obsidian when you already have project notes in Obsidian and want Smash agents to ingest them as source-backed knowledge. Smash copies Markdown notes into raw/obsidian/<vault>/, skips Obsidian plugin state, and blocks notes with secret-looking values before writing them.

smash init ~/Smash
smash import-obsidian ~/Documents/ObsidianVault ~/Smash
smash ingest-status ~/Smash

The import does not silently create durable memories. It stages raw source notes, then the normal ingest and proposal workflow decides what becomes wiki knowledge or reviewed memory.

Open The Smash Wiki

In Obsidian, choose Open folder as vault and select your Smash wiki folder:

~/Smash/wiki

For a project-local install, open that project's wiki/ folder instead. Smash uses regular Markdown files, YAML frontmatter, and [[wikilinks]], so Obsidian can read the pages directly.

Edit Safely

Prefer editing prose, titles, aliases, tags, summaries, and source notes. Be careful with lifecycle fields on memory pages, such as status, review_status, scope, project, and source, because agents use those fields to decide what is safe to recall.

Memory rule Use Smash commands or MCP tools for durable memory writes when possible. They check duplicates, conflicts, review state, and audit logs.

Keep Smash Indexes Current

After manual Obsidian edits, rebuild derived indexes and validate the wiki before asking agents to rely on the new content:

smash rebuild-index ~/Smash
smash rebuild-backlinks ~/Smash
smash validate ~/Smash
smash health ~/Smash

The local web viewer is still useful for Smash-specific views like health, ingest, memory review, captures, and MCP-ready query context. Obsidian is an editor/viewer for the same underlying files, not a replacement for Smash's validation and memory lifecycle.
