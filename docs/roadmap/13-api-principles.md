# 13 — API Principles

> Source: the historical roadmap source §14

## Shape

The HTTP API is **versioned and resource-oriented**, with action endpoints only where a state transition cannot be represented clearly as a resource update.

Use:

- stable IDs;
- cursor pagination;
- filtering;
- optimistic concurrency;
- idempotency keys;
- structured errors.

## Implementation contract

| Concern | Choice |
|---|---|
| Router and handlers | **Axum** |
| Cross-cutting behavior | **Tower** / **tower-http** layers — auth, tenant resolution, request IDs, tracing, timeouts, concurrency limits, compression |
| Request and response bodies | **Serde** |
| Input validation | **Garde** or **Validator**, applied at the edge before application services |
| Contract publication | **Utoipa** or **Aide** |

Handlers translate HTTP into application use cases. **Authorization, Rules, and Memory logic live in the core crate**, never in a handler — see [06 §6.1](06-service-architecture.md#61-rust-and-axum-are-the-product-backend).

### Errors

Define one application error type in the core crate and **one mapping** from it to HTTP status plus a structured body. Handlers do not construct ad-hoc responses.

A structured error carries: stable machine-readable code, human-readable message, request ID, and — where the error is a policy outcome — the Rule ID, version, and rationale. Error bodies never leak private Source content or token material.

**Panics are defects, not an error-handling strategy.** A panicking handler is a bug to fix, not a case to catch and reformat.

## Commands and queries

Separate command and query concerns **conceptually**, even when they share one Axum router.

- **Queries** may return projections optimized for Home, Board, Graph, Library, and Review.
- **Commands** invoke application services that enforce authorization, Rules, and Events.

**Do not let UI-specific payloads become the only canonical API.**

## Large and long work

- Large uploads use **object-storage flows** rather than proxying every byte through application memory. Where bytes do pass through the API, they stream — the whole body is never buffered.
- Long jobs return **Operation resources**.
- Streaming may be used for aggressive-search progress and event activity, **with a polling fallback**.

## Contract as artifact

- Publish an OpenAPI description generated by **Utoipa** (or **Aide**) and treat it as a **tested artifact** — CI fails when the committed description and the code disagree.
- Generate or validate SDKs only after the contract is stable.
- **MCP tools map to application use cases** rather than mirroring every HTTP endpoint.
