Lazy-load Smash through skills.

Official skills are small CLI workflows an agent can load when Smash is relevant: session start, retrieval, ingest, health, session-end proposals, and memory lifecycle.

On this page Why skills Included skills Use them Rules

Why Skills

MCP gives Smash structured tool calls, but it should not be the only path. If an agent can run local commands, it can use Smash through smash without an MCP server, background viewer, or extra client configuration. From a source checkout, the same workflows work with python3 smash.py.

The skills are intentionally proactive. Retrieval should load before work that may depend on previous context, health should load before trusting a changed wiki, ingest should load when raw files appear, and memory should load after important decisions or at session end so the agent can propose durable memory for review.

smash serve is optional

The web viewer is only for humans. Skills, CLI commands, and MCP tools all read the same local Markdown wiki directly.

Included Skills

The repo ships official skill folders under skills/:

SkillUse it forFirst command
smash-healthStart of Smash work, after installs/upgrades, interrupted writes, backups, repair, validation.smash health
smash-retrieveBefore answering context-sensitive work: bounded query packets, briefs, graph summaries, benchmarks.smash query "..."
smash-ingestWhen raw files are present: source ingest, stale sources, memory proposals, post-ingest checks.smash ingest-status
smash-memoryAfter important user-approved decisions or session end: propose, remember, recall, review, explain, update, archive, restore, forget.smash session-end

Use Them

Point your agent at the skill folder it supports, or copy the relevant SKILL.md into that agent's local skill directory.

skills/smash-health/SKILL.md
skills/smash-retrieve/SKILL.md
skills/smash-ingest/SKILL.md
skills/smash-memory/SKILL.md

Then use natural prompts that map to the skills:

is Smash ready?
start with Smash before we continue
seed this project into Smash
query Smash for the release process
end this session with Smash memory proposals
ingest raw/notes.md into Smash
remember that I prefer short release notes

Rules For Agents

Two additions with 1.6: if Smash session hooks are installed, the startup brief arrives automatically — skip the manual brief and go straight to bounded task recall. And when a brief reports a memory backlog, offer the user a read-only smash consolidate pass instead of letting captures pile up.

  • Prefer smash health when readiness is unclear, especially after an install, upgrade, restore, or broad wiki edit.
  • Start with smash start for readiness plus memory context, and use smash session-end to capture proposal-only memory candidates at the end of meaningful work.
  • Use smash seed . ~/Smash from a project directory when the user's wiki has no project context yet.
  • Prefer smash query, smash brief, and smash graph-summary over reading the whole wiki.
  • Use smash ingest-status before touching raw sources.
  • Do not silently create durable memory; use smash remember only when the user asks or approves a proposal.
  • Run smash validate and smash health after ingest or broad wiki edits.

Use MCP when you want structured tool calls inside an MCP client. Use skills when you want a lightweight, lazy-loaded CLI workflow.
