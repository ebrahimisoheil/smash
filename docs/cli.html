Command reference

Local commands for daily memory work.

Install the CLI with brew install ebrahimisoheil/smash/Smash on macOS, or use smash <command> after a global agent installer run. Smash uses smash because Smash is already a POSIX/macOS system utility. From a source checkout, use python3 smash.py <command> on macOS/Linux or py smash.py <command> on Windows.

CLI Tour

The CLI is independent of the web viewer. Use smash start, smash query, smash brief, smash session-end, smash health, and maintenance commands even when smash serve is not running. Agents that support lazy-loaded instructions can also use the official Smash skills instead of MCP setup.

Use smash try when you want the shortest proof loop: demo creation, readiness, query proof, brief proof, viewer command, and first agent prompts in one command.

Use smash proof when you want to prove the cross-agent memory loop directly: one clean local workspace, one reviewed memory, and one bounded recall packet shared by CLI, skills, and MCP.

Use smash onboard when you want to set up a real ~/Smash workspace: safe repair, health check, optional first memory, optional project seed, first prompts, and optional agent MCP wiring in one guided command. If the local viewer is running, /onboard mirrors that flow with copy buttons.

Use smash seed . ~/Smash from a project directory when you want Smash to create a source-backed project page from existing repo context before the first real recall. It scans allowlisted docs/rule files, blocks secret-looking values, and does not create durable memories silently.

Memory Commands

One rule for the memory knobs. Finding it → --trigger (a phrase that helps task-shaped recall find a recipe). Fencing it → --applies-when (conditions that demote or hide a memory outside its context). Owning it → --scope/--project/--visibility (whose memory it is and who may see it). Replacing it → --supersedes (archive the old claim with lineage; accepts the memory name or its title). Aging it → --review-after/--expires-at. When in doubt, save with none of them — every knob can be added later through review.

smash remember

Save a local agent memory. Strong duplicates and likely conflicts are refused unless explicitly allowed.

smash recall

Search local memories with recall readiness, project-aware filtering, type filters, and --as-of temporal recall.

smash recipes

List saved procedure memories with their triggers and first steps.

smash explain-memory

Show provenance, lifecycle, graph links, review issues, and recall readiness.

smash update-memory

Merge new text into an existing memory and reset review state.

smash archive-memory

Reversibly hide a stale or wrong memory from default recall.

smash forget-memory

Permanently delete a memory after explicit confirmation.

Capture Workflow

Use smash session-end at the end of a work session when an agent has notes or a transcript and should propose memory without saving it silently. Use lower-level captures for saved review inbox workflows.

smash session-end session-notes.md ~/Smash --project Smash --limit 3
cat transcript.md | smash session-end - ~/Smash --project Smash
smash capture-session session-notes.md --project Smash
smash capture-inbox --project Smash
smash accept-capture raw/memory-captures/<capture>.md --index 1
smash redact-capture raw/memory-captures/<capture>.md
smash delete-capture raw/memory-captures/<capture>.md --confirm

Use smash backup before broad repair work. Use smash benchmark when a wiki starts to feel slow or when you want to see how much broad wiki context the bounded packet avoided sending to an agent. smash status --validate and smash benchmark both show persistent-cache reuse so you can tell whether Smash is rereading every page or reusing unchanged records.

Use smash operations when health reports an interrupted write. If a marker has a rollback snapshot, run smash operations ~/Smash --recover <marker> to preview the recovery and add --confirm only after reviewing the plan.

Use smash team-sync before sharing Smash through Git. It is read-only: it checks Git state, verifies that raw/ is protected, checks whether review or visibility: private memories would make sharing unsafe, keeps wiki/log.md local to preserve each machine's audit hash chain, and prints paste-safe setup/sync commands without pushing private source material for you.

Use smash snapshot when you need a static, read-only HTML export for a teammate, maintainer, security reviewer, or demo. It excludes raw/, captures, local operation state, and memory pages by default. With --include-memories, it still excludes visibility: private memories unless --include-private-memories is explicitly passed.

Use smash connect <agent> when an agent already has Smash instructions but still needs MCP wiring. It previews the config before writing.

smash connect codex ~/Smash
smash connect codex ~/Smash --write
smash connect kiro ~/Smash --write
smash connect claude-code ~/Smash --hooks --write
smash verify-mcp ~/Smash

Add --hooks (Claude Code, Codex, Cursor) to also install session hooks: every new session then starts with a bounded Smash memory brief injected automatically, and session end stores proposal-only notes with memory candidates for later review — no durable memory is written without approval. Codex has no session-end event, so it gets the session-start brief only. Sessions without memory-worthy content are skipped and duplicate end events are deduplicated, so the capture inbox does not fill with noise. The hooks run smash hook session-start and smash hook session-end, which you can also invoke directly to inspect what they inject or capture. Codex and Cursor hook support is new and follows those vendors' documented hook schemas — if a hook misbehaves there, please open an issue. If the workspace runtime predates session hooks, --write refreshes it automatically.

Use smash recipes to list saved procedure memories with their triggers, and smash recall "<task>" --type procedure to recall only recipes. Consolidation plans also surface recurring themes across session captures — the review-gated way an agent learns your patterns: detection is automatic and deterministic, but turning a pattern into one durable memory is always proposed to you first. A scheduled idle-time agent session can run the plan as a "dream pass" and bring proposals to your next session.

Use smash consolidate when the capture or review backlog builds up. It is read-only: it counts pending captures and memories needing review, groups duplicate captures, and prints paste-safe accept/discard/review commands to run with the user. When the backlog crosses a threshold, the injected session-start brief nudges the agent to offer a consolidation pass, and MCP agents can request the same plan through review(action="consolidate").

Use smash semantic to inspect or enable optional hybrid recall. Lexical recall is always the default and the fallback; running smash semantic --setup once (or python3 -m smash_mcp --semantic-setup for MCP-only installs) adds a small local embedding model so paraphrased queries also find memories phrased differently — on Homebrew installs, where the runtime Python refuses direct pip installs, setup provisions the extras into ~/.smash-mcp-venv automatically. Recall itself never touches the network — the model loads offline-only, embeddings live in plain JSON under .smash-cache/, and semantic-only matches are labeled with capped confidence so agents verify before trusting them. Measured results and methodology live in benchmarks/RESULTS.md.

From a source checkout, use the synthetic large-wiki smoke when you want local scale evidence without touching your real wiki. The script prints the exact smash serve command and graph URL for the generated fixture.

python3 scripts/smoke_large_wiki.py --pages 10000
